# PDF 页面 OCR 与附件上下文

网页版 4.0.0 / Android 2.0.0。

- 在 PDF 本地预览、资料库阅读器或选页预览中点「OCR 识别」，使用已保存的 DeepSeek 官方 API 配置识别当前物理页。
- 在「加入对话」中选择「页面图片」或「OCR 文本 · DeepSeek」。OCR 文本模式保持输入框原样，把文字作为附件上下文发送给当前模型；页面图片仍保留，可展开预览和跳回来源页。
- 未缓存页面会发送渲染后的单页 JPEG 到官方 `POST /v1/tools/ocr`（`purpose=text_recognition`）。普通图片上传不进入此 PDF OCR 流程。
- 每页原始 OCR 文本、完成状态和识别时间保存在对应 PDF 文档记录中。重复加入、刷新、重开文档和备份恢复复用成功结果。内存任务合并与浏览器 Web Locks 防止同页并发重复请求。相同文件再次导入沿用已有资料库去重机制。
- OCR 使用 DeepSeek 官方配置；对话继续使用当前服务（包括兼容 API 和中转站）。可以选择已保存的官方配置，无需添加独立地址或 Key 字段。备份不保存任何 API Key。
- 失败不作为成功缓存；同一批中已经成功的页保留，重试只补缺页。服务返回 `length` 的不完整结果会保存并明确提示，不自动重复计费。
- 页面文字投影到请求时移除位置标记，但原始结果保留供查看；旧轮次 OCR 文字可继续进入上下文，不受普通图片最近一轮限制影响。
- 切换会话、关闭本地 PDF 面板或取消批量任务后，不把结果写入其他草稿；已经开始的识别可完成并保留缓存。服务端已接收请求后可能继续识别计费。

本地选页上下文保留现有单批 120 页限制。OCR 文字会占用当前模型的上下文，长文可能超过该模型上限。页面缓存与 PDF 存在当前浏览器/安装内；未备份时，清空数据或卸载会丢失缓存。

DeepSeek 原生文件解析是另一条链路：官方 API + deepseek-flash 使用 Files API 的 file_id；这些 ID 不发送给其他服务。独立 OCR API 返回的文本才用于跨模型上下文。

参考：[DeepSeek OCR 官方说明](https://api-docs.deepseek.com/zh-cn/guides/ocr/)、[原生文件解析](https://api-docs.deepseek.com/zh-cn/guides/document_parsing/)。
